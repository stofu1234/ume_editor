# UI の試作（GPUI、Mac）

[UI フレームワークの試作](../../docs/poc/ui-framework.md)のうち、Mac で作ったもの。Windows ARM64 で作ったものは [poc/gpui-textview](../gpui-textview/README.md) にある。2 つは別のコードで、キーの割り当ても違う（Windows 版は F7 でフォントの切り替え、Ctrl+= / Ctrl+- で文字の大きさ）。[ADR-0004](../../docs/adr/0004-ui-framework.md) を確定するための使い捨てのコードで、本番のコードは Phase 1 で作り直す。

- メインのワークスペースには入れていない（`poc/gpui` だけで 1 つのワークスペース）。CI の対象外
- GPUI は crates.io の `gpui-pre` 0.3.8（Zed の週次スナップショット。gpui-component 0.7 が使っているもの）を版固定で使う。公式の `gpui` は crates.io では 0.2.2（2025-10）で止まっている
- 測った結果と、作っていて分かったことは [ui-framework-result.md](../../docs/poc/ui-framework-result.md) に書く

## Mac で動かす

必要なもの

- Rust（版はリポジトリの `rust-toolchain.toml` で固定。rustup が自動で入れる）
- Xcode か Command Line Tools（ビルド中に libclang と codesign を使う）

Metal Toolchain（`xcodebuild -downloadComponent MetalToolchain`）は要らない。既定では、Metal のシェーダーを起動時にコンパイルする（`runtime-shaders` 機能）。

```sh
cd poc/gpui
cargo run --release                     # 空のウィンドウで起動
cargo run --release -- メモ.txt ...     # ファイルを開いて起動（1 ファイル 1 ウィンドウ）
```

まだないファイルを指定すると、サクラと同じく、その名前の空の文書として開く。保存したときにファイルができる。

初回のビルドは、Apple M1 の Mac でデバッグが約 1 分、リリースが約 1 分半かかる（依存のダウンロードを除く）。

### .app にまとめる

メニューバーにアプリ名を出したり、Finder の「このアプリケーションで開く」を試したりするときは、.app にまとめる。

```sh
poc/gpui/script/bundle-macos.sh
open poc/gpui/target/release/UmeEditorPoC.app
```

スクリプトは、リリースビルド、`Info.plist` の作成、アドホック署名、Launch Services への登録（「このアプリケーションで開く」の一覧に出すため）を行う。テキストファイルの既定のアプリにはならない。

### 環境変数

| 変数 | 内容 |
|---|---|
| `UME_POC_FONT` | 使うフォントのファミリー名（例: `UME_POC_FONT="BIZ UDGothic"`）。メニューにないフォントを試すとき |
| `UME_POC_FONT_SIZE` | 文字の大きさ（pt）。既定は 14 |
| `RUST_LOG` | GPUI のログ（例: `RUST_LOG=warn`） |

起動すると、最初の描画までの時間を標準エラーに出す（`ume-poc-gpui: first frame painted 160.2 ms after start`）。「ume_editor UI 試作について」にも、この時間とメモリの使用量を出す。

## できること

- 自前で描くテキスト表示: 行番号、改行マーク（LF ↓、CRLF ↵、CR ←）と [EOF]、カーソル行のアンダーライン、タブ（4 桁）。表示している行だけを描く
- 全角文字を半角 2 文字分の幅に揃える表示（サクラと同じ。設定メニューで切り替え）
- 文字の入力と削除、日本語入力（変換中の文字に下線を引き、候補ウィンドウを出す位置を IME に知らせる）。変換して確定した文字列は Undo 1 回で戻る
- カーソル移動、Shift での選択、マウスでの選択（ダブルクリックで単語、トリプルクリックか行番号のクリックで行）
- 元に戻す・やり直し、切り取り・コピー・貼り付け（改行コードは文書に合わせる）、大文字・小文字への変換
- 開く（ダイアログ、ウィンドウへのドラッグ & ドロップ、Finder から）、上書き保存、名前を付けて保存、閉じるときの保存の確認
- メニューバー: サクラの構成（ファイル / 編集 / 変換 / 検索 / ツール / 設定 / ウィンドウ / ヘルプ）。中身は数項目で、灰色の項目は配置だけ
- ツール > 100 万行のテキストを開く（スクロールの確認用）

文字コードは UTF-8 だけ（BOM 付きも可）。折り返しと検索はない。1 行の表示は 1 万文字まで。

## キー割り当て（Mac）

サクラの既定の割り当て（`sakura_core/func/CKeyBind.cpp`）の Ctrl を Cmd に読み替えた（[ADR-0008](../../docs/adr/0008-commands-and-keybindings.md) の提案）。Mac の作法と重なるキーは Mac に合わせた。

| キー | 操作 |
|---|---|
| ⌘N / ⌘O / ⌘S / ⇧⌘S | 新規作成 / 開く / 上書き保存 / 名前を付けて保存 |
| ⌘W / ⌘Q | 閉じる / 終了 |
| ⌘Z / ⌘Y・⇧⌘Z | 元に戻す / やり直し |
| ⌘X / ⌘C / ⌘V / ⌘A | 切り取り / コピー / 貼り付け / すべて選択 |
| ⌘F6 / ⌘F7、⌥⌘L / ⇧⌥⌘L | 選択した英字を小文字 / 大文字に変換（サクラの「小文字」「大文字」） |
| ←→↑↓、Shift で選択 | カーソル移動。選択中の ←→ は選択を解除するだけ（サクラと同じ） |
| ⌘← / ⌘→、Home / End | 行頭 / 行末 |
| ⌘↑ / ⌘↓、⌘Home / ⌘End | ファイルの先頭 / 最後 |
| PageUp / PageDown | 1 ページ移動 |
| ⌃⌘Space | 絵文字と記号 |
| ⌘= か ⌘+ / ⌘- | フォントサイズ拡大 / 縮小（⌃= / ⌃+ / ⌃- でも可） |

- サクラの Ctrl+W（単語選択）と Ctrl+←→（単語単位の移動）は、Mac では閉じると行頭・行末に使われるので、Mac の意味にした
- Mac のキーボードで F1〜F12 を使うキー（⌘F6 など）は、fn を押しながら押す。fn なしでは、明るさや音量、再生などのキーになる（システム設定 > キーボード > キーボードショートカット > ファンクションキー で変えられる）
- JIS キーボードでは、⌘= は ⌘⇧-（= のキー）、⌘+ は ⌘⇧;（+ のキー）で押せる
- フォントサイズのキーはサクラにない（サクラは Ctrl+ホイール）。ほかのアプリに合わせ、Windows と同じ ⌃ でも押せるようにした（ADR-0008 の「Ctrl のままの配列」の案）
- フォントの切り替えはメニュー（設定 > フォント）だけで、キーは割り当てていない（Windows 版は F7）

## 確認の手順

[試作の確認項目](../../docs/poc/ui-framework.md#確認項目)を Mac で確かめる手順。

1. 日本語入力: 標準の日本語入力（ライブ変換のオンとオフ）と Google 日本語入力で、文の入力、変換、文節の移動、確定、取り消し（Esc）、再変換を試す
2. 文字の見え方: 設定 > フォント で切り替え、12〜14pt で見比べる。設定 > 全角文字を半角 2 文字分の幅に揃える をオフにすると、フォントの字幅そのままで描く
3. 起動時間: `cargo run --release` か .app で起動し、標準エラーかバージョン情報の時間を見る
4. スクロール: ツール > 100 万行のテキストを開く で開き、トラックパッドとマウスでスクロールする。⌘↓ で末尾へ移動する
5. メモリ: 小さいファイルを開いた状態で、アクティビティモニタの「メモリ」かバージョン情報の RSS を見る
6. メニューとショートカット: 上の表のキー、⌘Q、⌘H、⌘M、閉じるボタンの変更済みの印（●）を試す
7. ほかの環境: Windows と Linux で同じ手順でビルドする（未確認）

## 自己確認モード

アプリ自身がキー入力と日本語入力の呼び出しを流し込み、ウィンドウの描画結果を PNG に保存して終了する。macOS の画面収録やアクセシビリティの許可なしで、表示と入力の経路が動くかを確かめられる。本物の日本語入力の確認（手順 1）の代わりにはならない。

```sh
cargo run --features self-check -- --self-check /tmp/ume-check [ファイル]
```

`opened.png`（起動直後）、`composing.png`（変換中）、`typed.png`（確定と選択のあと）、`sample.png`（100 万行の 50 万行目付近）を保存し、最後に `self-check: ok` を出す。途中で次のことも確かめる。

- コマンドラインで指定したファイルが、どのウィンドウで開いたか
- Mac では、フォントサイズと大文字・小文字のキーを macOS のキーイベントとして流す。キーボードの種類（JIS など）を付けたイベントなので、GPUI がキーボード配列をどう読んだかが分かる（例: `⌘= = cmd-= → ume::FontSizeUp`）
- まだないファイル（`<dir>/新規.txt`）を開いて保存すると、ファイルができる

## 構成

| ファイル | 内容 |
|---|---|
| `src/main.rs` | 起動、ファイルを開く処理、アプリ全体のコマンド |
| `src/actions.rs` | コマンド（サクラの機能名に合わせた名前）と既定のキー割り当て |
| `src/menus.rs` | メニューバー |
| `src/editor.rs` | エディタのビュー。コマンドの処理、IME との受け渡し、保存 |
| `src/element.rs` | テキスト表示の描画（行番号、選択、キャレット、桁揃え） |
| `src/document.rs` | 文書のモデル（ropey、選択範囲、IME の変換中の文字列、Undo）。UI に依存しない |
| `src/settings.rs` | フォントと表示の設定 |
| `src/self_check.rs` | 自己確認モード |
| `script/bundle-macos.sh` | .app を作るスクリプト |

テスト: `cargo test`（文書モデルと保存処理）。clippy: `cargo clippy --all-targets -- -D warnings`。
