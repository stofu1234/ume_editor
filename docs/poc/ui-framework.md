# UI フレームワークの試作

[ADR-0004](../adr/0004-ui-framework.md) を確定するための試作。GPUI で作り、基準を満たさない項目があれば Iced でも同じものを作って比べる。

## 進め方

- まず Windows ARM64 で行う（[ADR-0009](../adr/0009-initial-development-target.md)）。コードは WSL2 の Claude Code で書き、Windows 側でビルドして起動する
- macOS に固有の項目（メニューバー、macOS の日本語入力、Finder との連携）は、Mac での作業を始めたときに確かめる
- 期間は数日に区切る。試作のコードは捨てる前提でよい（本番のコードは Phase 1 で作り直す）
- 結果は `docs/poc/ui-framework-result.md` に書き、ADR-0004 を更新する

## 作るもの

- ウィンドウ 1 つに、自前で描くテキスト表示（行番号付き、等幅フォント）。表示している範囲の行だけを取り出して描く（Phase 1 以降の本番と同じ形）
- 文字の入力と削除、矢印キーでのカーソル移動
- macOS のメニューバー（サクラの構成: ファイル / 編集 / 変換 / 検索 / ツール / 設定 / ウィンドウ / ヘルプ。中身は数項目でよい）
- ファイルを開く（ダイアログと、ウィンドウへのドラッグ & ドロップ。Finder の「このアプリケーションで開く」は、.app にまとめられたら確認する）

## 確認項目

| # | 項目 | 確かめ方 | 基準 |
|---|---|---|---|
| 1 | 日本語入力 | Windows では Microsoft IME と Google 日本語入力、macOS では標準の日本語入力（ライブ変換のオンとオフ）と Google 日本語入力で入力する | 変換中の文字が入力位置に出る。候補ウィンドウが入力位置の近くに出る。確定や取り消しで文字が重複・欠落しない |
| 2 | 文字の見え方 | Windows では BIZ UD ゴシックや MS ゴシック、macOS では等幅の英字フォント＋ヒラギノや Osaka−等幅などを 12〜14pt で表示して見る | ぼやけやにじみが気にならない（ユーザーが判断する） |
| 3 | 起動時間 | Release ビルドで、起動から最初の描画までを測る | 体感で待たない（目安は 0.3 秒以内） |
| 4 | スクロール | 100 万行のテキストを表示してスクロールする | 引っかかりがない |
| 5 | メモリ | 小さなファイルを開いた状態で測る | 記録する（基準は結果を見て決める） |
| 6 | メニューとショートカット | 上の「作るもの」が macOS の作法どおりに動くか、Cmd+Q などの標準動作も含めて試す | 違和感がない |
| 7 | ほかの環境 | 同じコードを Windows x64 の実機、Linux、Mac でビルドして起動し、入力する | 起動して入力できる |
| 8 | AI での開発のしやすさ | API の変化や資料不足で手戻りした回数と内容を、試作中に記録する | 記録する（判断材料にする） |
